# 비레스 5083 기본 시작과 이야기 서고 접근성 설계

- 작성일: 2026-08-01
- 상태: 기본 방향 승인, 명칭·브랜드·말미 참고 설명 개정안 검토 대기
- 대상: 비레스 5083 이야기 서고 공개 페이지
- 기준 시작상황: LunaTalk 비레스 캐릭터 `char_idx=70170`, 기본 시작 `idx=0`

## 1. 배경

현재 비레스 챗봇에는 기본 시작 하나와 역할형 시작 일곱 개가 있다. 공개 이야기 서고는 역할형 시작 일곱 개를 모두 다루지만, 별도 호출어 없이 시작하는 기본 상황은 독립 열람 흐름으로 제공하지 않는다.

기본 시작에서 사용자는 도시에 막 도착한 자유 여행자다. 성문 집행자 베켈 오르민은 낡은 목패를 압수하거나 위조품으로 단정하지 않고, 목패가 사용자 손에 들어온 경로와 비어 있는 보증인 칸을 설명하라고 요구한다. 따라서 이 흐름은 이름, 소유, 허가, 보증, 표식과 현재 권한을 이해하게 하는 기록을 우선해야 한다.

현재 공개 명칭인 `시작상황별 기록`은 정확하지만 관리 항목처럼 들리고, 처음 방문한 사용자가 무엇을 할 수 있는지 바로 알기 어렵다. 본문에는 `첫째 종`, 지역 달력, 화폐와 관청 용어처럼 세계 안에서는 자연스럽지만 첫 독자에게는 낯선 표현도 있다. 이를 본문 중간에서 설명하면 편지, 장부와 공문서라는 형식이 깨지므로, 원문은 유지하고 문서가 끝난 뒤에만 짧은 참고 설명을 제공한다.

## 2. 목표

1. 기본 시작을 기존 역할형 시작과 같은 수준의 독립 상황 카드로 제공한다.
2. 사용자가 현재 검문에 필요한 판단 기준을 기존 기록 네 편에서 자연스럽게 추론하게 한다.
3. 기본 시작과 성문 야간 경비를 제목, 역할, 갈등과 이미지에서 명확히 구분한다.
4. 기존 14편 원문과 30개 삽화는 수정하거나 재생산하지 않는다.
5. 기존 역할형 시작 일곱 개의 문서 구성과 읽음 상태를 보존한다.
6. 공개 명칭만 보고도 비레스의 이야기 문서를 시작상황에 따라 읽는 페이지임을 알 수 있게 한다.
7. 비레스 세계의 낯선 시간, 화폐, 달력과 행정 맥락을 원문이 끝난 뒤 확인할 수 있게 한다.
8. 공개 화면과 생성 데이터의 세계 명칭을 `비레스 5083`으로 통일한다.

## 9. 문서 말미 참고 설명

### 9.1 배치 원칙

참고 설명은 14편 모두에서 인세계 원문과 모든 삽화가 끝난 다음에 한 번만 표시한다. 본문 문단 사이, 삽화 캡션, 상황 카드와 문서 첫머리에는 넣지 않는다.

표시 제목은 `읽고 나서 참고`로 고정한다. 접힌 도움말이나 팝업으로 숨기지 않고 바로 읽을 수 있게 하되, 종이 프레임 밖의 별도 영역으로 구분하여 저자가 쓴 원문의 일부로 오해하지 않게 한다.

각 문서는 필요한 만큼 1~5개 항목을 가진다. 항목 수를 억지로 맞추지 않으며 다음만 설명한다.

- 시간: `첫째 종`, `스물여섯째 종`처럼 하루 안의 시점을 세는 방식
- 달력: 녹지절력, 해도력, 명예력처럼 서로 다른 주기와 날짜 표기
- 화폐와 단위: 은량, 동각, 철각과 환산 관계
- 행정과 생활 맥락: 보증인, 봉인틀, 승인점, 관할, 물때처럼 사건 이해에 필요한 말
- 지역 이름: 관청명과 생활명이 달라 혼동될 수 있는 경우

### 9.2 작성 규칙

참고 설명은 정본 사실을 쉬운 말로 정의하되 사건의 정답을 대신 말하지 않는다.

1. 한 항목은 `용어 + 1~2문장 설명`으로 끝낸다.
2. 화자가 거짓말했는지, 누가 책임자인지와 같은 해석은 적지 않는다.
3. 본문에 없는 새 설정, 추정과 작가 해설을 추가하지 않는다.
4. 같은 용어라도 해당 문서에서 필요한 범위만 설명한다.
5. 본문 문체를 흉내 내지 않고, 현대 독자를 위한 중립적이고 쉬운 문장으로 쓴다.

예시는 다음과 같다.

| 용어 | 설명 |
|---|---|
| `첫째 종` | 비레스의 하루를 스물여섯 번으로 나누어 세는 시간 표현입니다. 첫째 종은 그날의 첫 시간대입니다. |
| `스물여섯째 종` | 하루의 마지막 시간대입니다. 이 종이 지나면 다음 날의 첫째 종으로 넘어갑니다. |
| `녹지절력·해도력·명예력` | 같은 해를 서로 다른 길이의 주기로 세는 지역 달력입니다. 같은 `둘째 주기 여덟째 날`도 달력에 따라 실제 날짜가 달라질 수 있습니다. |
| `은량·동각·철각` | 비레스에서 쓰는 화폐 단위입니다. 1은량은 12동각 또는 60철각입니다. |

### 9.3 데이터와 화면 구조

참고 설명의 정본은 `00_관리/초기열람_참고설명_v1.json`에 문서 ID별로 둔다. 원문 Markdown과 분리하여 14편의 문장과 화자 목소리를 그대로 보존하고, 빌더가 이를 공개 문서의 `references` 배열로 병합한다.

```json
{
  "id": "ini-com-01",
  "html": "<p>인세계 원문...</p>",
  "references": [
    {
      "term": "스물여섯째 종",
      "explanation": "하루의 마지막 시간대입니다. 이 종이 지나면 다음 날의 첫째 종으로 넘어갑니다."
    }
  ]
}
```

리더 화면은 `article.reader-document`가 끝난 뒤, 읽음 완료 조작보다 앞에 `aside.reader-references`를 렌더링한다. 제목은 실제 heading 요소로 제공하고 각 용어와 설명은 의미가 연결되는 목록 구조로 표시한다. 참고 설명이 원문 종이 프레임 안에 겹치거나 삽화 위에 올라가서는 안 된다.

## 10. 데이터 구조

정본 마스터 인덱스의 문서 수 의미는 유지한다.

- `alwaysVisible`: 공통 문서 7편
- `roleLinked`: 역할 문서 7편
- `totalPlanned`: 전체 원문 14편
- `defaultFlowCount`: 기본 시작 독서 흐름 1개
- `readingFlows`: 기본 시작 1개와 역할형 시작 7개, 총 8개
- `00_관리/초기열람_참고설명_v1.json`: 14편 참고 설명의 정본
- `documents[].references`: 14편 각각의 문서 말미 참고 설명 1~5개

`readingFlows.length === roleLinked`라는 기존 검증은 `readingFlows.length === roleLinked + defaultFlowCount`로 변경한다. 역할 문서 고유 수 검증은 계속 7편을 요구한다.

`visiblePerStart`는 원문 설계상의 `공통 7편 + 역할 1편` 의미를 유지한다. 공개 페이지의 카드당 추천 네 편 수와 혼용하지 않는다.

## 13. 접근성 근거

페이지 제목과 첫 heading은 짧고 고유하며 페이지의 목적을 직접 설명해야 한다. 낯선 단어와 암시된 맥락은 쉬운 말로 설명하되, 논리적인 heading과 구역으로 분리한다. 이 원칙에 따라 몰입용 이름인 `이야기 서고`와 행동을 설명하는 첫 화면 제목을 함께 쓰고, 낯선 용어는 원문 뒤의 별도 heading 아래 제공한다.

- [W3C WAI, Clear and Understandable Content](https://www.w3.org/WAI/WCAG2/supplemental/objectives/o3-clear-content/)
- [W3C WAI, Use Clear Words](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o3p01-clear-words/)
- [W3C WAI, Writing for Web Accessibility](https://www.w3.org/WAI/tips/writing/)
- [W3C WAI, Page Structure and Headings](https://www.w3.org/WAI/tutorials/page-structure/headings/)
